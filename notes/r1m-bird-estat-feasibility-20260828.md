## 0. 認証不要でデータ本体に到達できるか（経路の確定）

**到達できる。** ただし到達の仕方に一手要る。

* 統計表一覧のページ（`/stat-search/files?...`）は**表の一覧を JS で読み込む**ため、
  素の HTML には表 ID が出ない。
* **`layout=dataset` を付けると server-side で描画され、`statInfId` が直接取れる**。
  ここから `/stat-search/file-download?statInfId=<id>&fileKind=<k>` の**単純な GET**で
  本体が落ちる（実測：HTTP 200、`Content-Disposition` つき）。
* `fileKind` は表ごとに違う（実測：`0`=xls、`1`=CSV、`2`=PDF）。

**参考（使っていない経路）**：データベース表の CSV は
`/dbview/api_download_create` → `/dbview/api_download_run` の2段 POST で、
**認証は不要だが**選択条件を gzip+base64 した引数を要する（`convertToPostData` を実測）。
今回は**この経路を使わずに済んだ**ので手を付けていない。

## 8. suite 化の概算工数と、成立を疑う点

### 概算工数

既存の `build_v3.py` / `build_v4.py` の型に乗る。

| 作業 | 見積り |
| --- | --- |
| 取得（`layout=dataset` から statInfId 収集 → CSV 取得）と CP932 の正規化 | 1〜1.5時間 |
| コード表の取り込み（候補1＝本体から生成／候補2＝dbview HTML から抽出） | 0.5〜1時間 |
| 6段ラダーの生成（どのコードの意味を書くかで段を作る） | 1〜2時間 |
| 正答の独立計算と二経路検査を selftest に | 1時間 |
| リーク検査の一段 | 1時間 |
| **合計** | **4.5〜6.5時間** |

**GPU 走行は別。**

### 成立を疑う点

1. **リークの規模が未知。** `30100`→だいこん、`01200`→結核 のような対応をモデルが
   覚えている可能性がある。**e-Stat も公開データで学習に入り得る。**
   前回報告（`notes/r1m-bird-feasibility-20260828.md` 第5節）で提案した
   定義なし直接問いを、**候補確定より先に**回すべきだと考える。
   なお候補1の品目コードは5桁の**調査固有体系**で、`16001`（国土数値情報の学校分類）より
   一般公開の露出が少ない可能性はあるが、**測っていないので推測**。
2. **利用規約の「別紙」を確認できていない。** 別の利用ルールが適用される表の一覧が
   参照できず、**候補2件がそこに載っていないことを確認できていない**。
3. **候補1にはコード定義表が別置で存在しない。** 分離は「こちらが本体から作る」形になり、
   **未出現コードの存在を知る手段がない**。厳密さを取るなら候補2。
4. **候補1は速報・日別で、日々更新される。** ラン記録に**取得日時と statInfId を固定**して
   残さないと再現できない（`P29` の年度問題と同型）。
5. **候補2には度数0のカテゴリが実在する**（139中5種）。課題に使うと答えが0になる。
6. **候補1には合計行が混在する**（産地コード空欄、200行中58行）。
   除かずに数えると二重計上になる。
7. **CP932。** UTF-8 前提のパースは落ちる。候補2では一部バイト列が CP932 でも
   復号できず `errors='replace'` を要した——**元データに文字コードの乱れがある**可能性。
8. **候補2の1文書が大きい。** 全29,607行を1文書にすると X_tok を大きく超える。
   地域スライス（全国＝417行）なら収まるが、**スライスの切り方が難度を決めてしまう**。
