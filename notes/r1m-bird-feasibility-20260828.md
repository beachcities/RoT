## 4. 正答を独立計算で検証できる集計課題の成立例

**「この列とこのコード表で検証可能な問いが立つ」ことを確認した。**

**成立例**：`P29_003`（学校分類）と `SchoolClassCd-v2_0.html` の対応表を使い、
**島根県の「小学校」と「中学校」の合計件数**を問う。

* コード表から `16001=小学校`、`16002=中学校` を機械的に取得。
* **経路A**（GeoJSON をパースし、コード表と突き合わせて数える）：**291 件**
* **経路B**（同じ zip 内の `.dbf` をバイナリで直接読む**別実装**で数える）：**291 件**
* **両経路が一致。** レコード数も dbf 503 / GeoJSON 503 で一致。
* 内訳：小学校 196、中学校 95。

**正答が独立に検証できることを実測で確認した**——同じファイルの別表現（GeoJSON と
dbf）を別コードで数え、値が一致している。

### 落とし穴になり得る点（設計材料として）

`P29_007`（休校区分）は `0=調査なし / 1=開校中 / 2=休校中`。
問いに「休校中を除く」を付けると**もう1つコード表が要る**構造になる。
ただし**島根県の小中291件はすべて `1`（開校中）で、休校中は県全体で0件**。
この県では条件を付けても答えは 291 のまま動かない。
**弁別力のある県を選ぶか、別の属性を使う必要がある**（実測に基づく指摘）。

## 5. 定義なし直接問いのリーク検査（形の提案・実装しない）

同じデータ本体と同じ問いを与えたまま**コード表だけを外し**、属性コードの意味を
直接問う一段を置く——「この文書の `P29_003` が `16001` であるレコードは、何を表す
施設か。文書に書かれている情報だけで答え、書かれていなければ『判定不能』と答えよ」。
コード表を与えていないのだから文書内在の情報からは答えられないはずで、
**ここで `小学校` と当ててくる分は、文書ではなく事前知識から来ている**。国土数値情報は
公開データで学習に入っている可能性が高く、`16001` のような公的コード体系は特に
覚えられやすいので、この検査は**梯子の全水準に先立つ前提条件**として置くのがよい。
正答率が偶然水準を超えるコードは**課題に使わない**——使えば、その水準で測っているのが
「文書を読む力」ではなく「コードを覚えているか」になってしまう。合成データ（v3系）では
コードを自分で作れるので生じなかった問題で、**実データ版に固有**である。

## 6. suite 化の概算工数と、成立を疑う点

### 概算工数

既存の `build_v3.py` / `build_v4.py` の型（レコード群を読み、水準ごとに
「文書に何を書くか」を変えて JSON を吐く）にそのまま乗る。

| 作業 | 見積り |
| --- | --- |
| 取得・解凍・GeoJSON → レコード群への正規化 | 1〜2時間 |
| コード表5種の機械可読化（列名で拾う・xlsx 回避） | 0.5〜1時間 |
| 6段ラダーの生成（どのコードの意味を書くかで段を作る） | 1〜2時間 |
| 正答の独立計算と検査（dbf 経路での二重計算を selftest に） | 1時間 |
| リーク検査（第5節）の一段 | 1時間 |
| **合計** | **4.5〜7時間** |

**GPU 走行は別**（v3系と同じ経路なら、モデル・水準数・反復数に比例）。

### 成立を疑う点

1. **リークの規模が未知。** 第5節の検査を回すまで、`16001`→小学校 のような対応を
   モデルがどれだけ覚えているか分からない。**大半のコードで漏れていれば、実データ版
   そのものが成立しない。最初に確かめるべきはここ**だと考える。
2. **N03 の但し書き。** 「二次利用に国土地理院への申請が必要な場合がある」の射程が
   個別ページから読み取れない。N03 を使うなら確認が要る（P29・P04 にはこの但し書きが
   ない）。
3. **年度で許諾条件が変わる。** P29 は 2013年度のみ非商用で、日付なし URL は
   2013年度版を指す。**年度付き URL を固定し、ラン記録に年度を残す**必要がある。
4. **1県あたり503件は v3 の17件より一桁多い。** 文書に全レコードを載せると
   プロンプトが大きくなる。**県を絞るかレコードを間引く**設計が要り、間引き方が
   恣意的だと課題の難度がそこで決まってしまう。
5. **「効かない属性」がある。** 島根県では休校中が0件で、条件を足しても答えが動かない。
   **弁別力を持つ属性・地域の選定が要る。**
6. **属性番号が版で変わる。** 2013年度版の P29 では学校分類が `P29_004`、
   2023年度版では `P29_003` と**同じ意味が別番号**になっている。版を跨ぐと
   コード表と属性名の対応が崩れる。
